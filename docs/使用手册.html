01

项目概览

这是一个独立的 STM32F407VE 嵌入式框架工程。内核是官方 RT-Thread Nano 3.1.5，上层是自建 mr 风格设备核心（pin/serial/spi/display），板级层参考 mr-library 的 src/platform/<vendor> 组织方式。

01 / Abstraction

mr 风格设备核心

核心只保存“路径 → 设备对象”。pin / serial / spi / display 各自是独立 class；新增类型不用改 core/fw_dev.c。

02 / Configuration

Kconfig 单一配置源

一次生成 rtconfig.h、board_config.h、fw_config.h、app_config.h、board_memory.ld 和 CMake 变量，不再维护多份配置。

03 / Kernel

真正的 Nano 3.1.5

源码来自官方 pack，包含 scheduler.c / cpu.c 结构；只对 GCC 14 做了 IT-block 汇编补丁。

当前验证状态

Host tests 5 / 5 单测 + profile/manifest/Keil 检查
HSI build 82.4 KB Flash · RAM 10.9 KB
HSE build 82.5 KB 168 MHz · RAM 10.9 KB
HIL 待上板 脚本已就绪
范围说明 Host 测试与 ARM 固件构建已经通过；真实硬件 HIL 需要板卡、USB-UART 和 ST-Link/CMSIS-DAP，当前手册不声称已完成上板验证。
02

架构与目录

整改后的结构是“mr 风格设备核心 + 实例表驱动 BSP + 单一配置源”。 应用只通过 fw_dev_* 访问设备，board 只负责时钟和注册。

↓

mr 风格 device core

c · fw/dev.h
struct fw_dev_ops {
    fw_status_t (*open)(fw_dev_t *dev);
    fw_status_t (*close)(fw_dev_t *dev);
    int (*read)(fw_dev_t *dev, int off, void *buf,
                size_t size, uint32_t timeout_ms);
    int (*write)(fw_dev_t *dev, int off, const void *buf,
                 size_t size, uint32_t timeout_ms);
    int (*ioctl)(fw_dev_t *dev, int off, int cmd, void *args);
    int (*isr)(fw_dev_t *dev, int event, void *args);
};

与 mr-library 的对应

mr-library本项目说明
mr_dev_*fw_dev_*保留 open/close/read/write/ioctl/isr 语义
mr_pin + 引脚编号pin + (port << 4) | pin一个设备覆盖所有 GPIO
mr_serial + serialNserialN每实例一个设备，ring 静态
drv_pin.c + stm32f407_pin_map.h同名/同结构端口、引脚、IRQ 表
mr_malloc ring静态 ring无堆、RAM 可预测
MR_INIT_*_EXPORTboard 显式注册避免链接段差异，启动顺序直观

单一配置源与源文件清单

  • profiles/<profile>/{defconfig,.config,generated/} 是唯一配置源；CMake 与 Keil 共用。
  • project/sources.json 是 CMake 与 Keil 共用的源文件清单。
  • tools/gen_keil.py 从 manifest + keil/project_template.uvprojx 生成 Keil 工程。

依赖红线

  • src/framework/core 与 components 不包含 HAL / RT-Thread 头文件。
  • core/fw_dev.c 不认识 pin/serial/spi/display；类型令牌由 class 模块定义。
  • ISR 只写 ring、发送事件；不在 ISR 里调用 read / write / display。
  • 默认 RT_USING_HEAP=n，设备、ring、事件全部静态分配。

初始化顺序

boot sequence
rt_hw_board_init()          // 调度器启动前
  stm32f407_boot_init(board_clock_config())
    HAL_Init / NVIC 分组 4 / 时钟 / SysTick / heap / 复位原因
  board_devices_init()
    board_pins_validate()     // 端口/AF/SWD/重复引脚
    drv_pin_register()        -> "pin"
    drv_serial_register_all() -> "serial1..N"
    stm32f407_console_bind()  // 绑定控制台
    drv_spi_register_all()    -> "spi1..N"
    LCD 引脚 + st7735s_init   -> "lcd"

main()                      // RT-Thread main 线程
  fw_dev_open(console/pin)
  board_serial_start_all()     // arm 所有启用串口
  app_boot_display(board_lcd())  // 面板初始化 + 启动画面 + 背光
  app_tasks_init()          // manager + adopt main + create rpc
  app_rpc_init(config.tasks=manager) + 1s 上报
  app_tasks_start()         // 启动 rpc 任务
  fw_task_refresh() + fw_task_next_wait_ms() + mdelay  // 监督循环

rpc 任务
  fw_task_heartbeat_self()
  app_rpc_poll() + fw_serial_wait_rx()  // 等待上限 500ms

UART 行为

  • RX：RXNE 中断 → serial class ring → rt_event_send 唤醒任务。
  • TX：任务写 ring → 驱动 start_tx → TXE 中断继续搬运。
  • USART IRQ 在 drv_serial.c 内按 FW_USING_UARTn 定义。
  • serial class 通过 driver 的 lock/unlock（PRIMASK）保护 ring。
  • DMA/EXTI 框架已实现，默认走 IT；f407ve-dma 启用 UART1 DMA 与 pin EXTI。

LCD

ST7735S 驱动通过 fw_dev_t（spiN + pin）工作，不直接包含 HAL 类型。CS/DC/RES/BL 都是 pin 设备上的编号。

设备抽象 API

设备核心只维护“路径 → 设备对象”。pin/serial/spi/display 各自定义类型令牌和 ops； 新增设备类型不需要修改 core/fw_dev.c。

查找与打开

c · open devices
fw_dev_t *serial = fw_dev_find("serial1");
fw_dev_t *pin = fw_dev_find("pin");
fw_dev_t *spi = fw_dev_find("/dev/spi1");
fw_display_t *display = fw_display_find("lcd");

fw_dev_open(serial, FW_OFLAG_RDWR);
fw_dev_open(pin, FW_OFLAG_RDWR);

引脚：一个设备覆盖所有 GPIO

c · pin numbering
/* 高 4 位端口（0=A），低 4 位引脚号 */
int led = FW_PIN_NUMBER(4, 2);  /* PE2 = 66 */

fw_pin_configure(pin, led, FW_PIN_MODE_OUTPUT);
fw_pin_write(pin, led, 1);
fw_pin_read(pin, led);

串口：serial1..N

c · serial
uint8_t buf[64];
int n = fw_dev_read(serial, 0, buf, sizeof(buf), 0U);
/* n == 0：暂无数据；n < 0：错误 */

n = fw_dev_write(serial, 0, data, length, 0U);
/* n 是本次接受的字节数；未全部接受时下一轮重试尾部 */

fw_serial_wait_rx(serial, 100U);

fw_spi_config_t cfg = {12000000U, 0, 1};

fw_display_setup(display);

新增设备类型

接口

新增 src/framework/include/fw/adc.h：类型令牌、ops、fw_adc_t。

class

新增 src/framework/core/fw_adc.c：ioctl/read 包装，不涉及芯片。

08

RT-Thread Nano 集成

内核是官方 Nano 3.1.5，不是 v5.x 的裁剪拷贝。工程只保留内核、Cortex-M4 libcpu 和最小配置，不启用设备框架、FinSH、ulog。

目录内容说明

src/vendor/rt-thread-nano/srcscheduler · ipc · clock · thread · timer · kservice · mem*内核源文件

SysTick 与 HAL tick

c · one tick source
void SysTick_Handler(void)
{
    rt_interrupt_enter();
    HAL_IncTick();
    rt_tick_increase();
    rt_interrupt_leave();
}

drv_common.c 强覆盖 HAL_InitTick、 HAL_IncTick、HAL_GetTick、HAL_Delay。 调度器启动前延时忙等，启动后走 rt_thread_mdelay。

Console

未启用 RT_USING_DEVICE，所以 stm32f407_console.c 提供强符号 rt_hw_console_output()。启动阶段直接轮询 TXE/TC； 运行期只做非阻塞入队，避免在中断/故障上下文阻塞。

静态分配与链接

  • main / rpc / idle 线程静态；main 栈 4 KB、rpc 栈 2 KB、idle 栈 512 B。
  • main 是健康监督者；rpc 独占串口，等待上限 500 ms；默认不启用软定时器线程。
  • 任务表、线程对象和栈都在 .bss；不启用 RT_USING_HEAP。
  • 链接使用 entry 作为 ELF 入口，启动文件调用 entry()。
  • PendSV_Handler / HardFault_Handler 由 Nano libcpu 强定义，board 不重复定义。
  • SysTick_Handler、rt_hw_console_output、HAL tick 覆盖放在 OBJECT library，避免被静态库里的 weak 版本遮蔽。

协议与 HIL

线协议与旧版保持兼容：同一帧格式、命令码、CRC 和主动上报格式。 Host 测试和真实串口 HIL 使用同一套解析逻辑。

帧格式

A55A LENSEQCMDPAYLOAD CRC_LOCRC_HI
LEN = payload 长度 0..32 CRC-16/CCITT-FALSE · init FFFF · poly 1021 CRC 覆盖 LEN..PAYLOAD

STATS0x04空状态 + frames / io_errors / partial_timeouts / report_seq

回复命令为请求命令 | 0x80；SEQ 沿用请求值；回复帧不再回复，避免协议循环。

主动上报

  • 上电启动并完成串口初始化后，首次在 1 秒后发送。
  • 使用独立序号空间，0..255 回绕。
  • 错过的周期合并，不补发突发。
  • LED 未知时 payload 为 00 00 00。

扩展指南

最常见的扩展是新增外设、换板子和增加命令。原则是：接口层不动，驱动和装配分层增加。

新增一个 STM32 外设驱动

接口

在 src/framework/include/fw/ 定义 ops 和类型化对象；如果已有接口（pin/uart/spi/display），直接复用。

芯片驱动

在 src/platform/stm32f407/ 实现 HAL 适配，不包含 board 引脚。

板级实例

在 src/platform/board/stm32f407ve/board_devices.c 放静态实例、配置引脚并注册设备名。

构建

在 project/sources.json 登记源文件；Kconfig 增加 enable 选项（可选）。

新增一条 RPC 命令

c · app_rpc.c
static void cmd_hello(app_rpc_t *app,
                      const fw_message_t *request,
                      fw_message_t *reply)
{
    (void)app;
    if (request->length != 0U) { reply->payload[0] = 1U; return; }
    reply->length = 6U;
    memcpy(&reply->payload[1], "HELLO", 5U);
}

/* 在 command_table 中增加： */
{ 0x05U, cmd_hello },

同步更新 HIL 脚本和帧格式文档；未识别命令仍统一返回状态码 2。

换一块 STM32F4 板

  • 新建 src/platform/board/<board>/：board.c、board_devices.c、board_clock.c、board_pins.c、Kconfig.board、link.lds。
  • 如果仍是 STM32F407，可复用 src/platform/stm32f407 与 stm32f407_map。
  • 如果换芯片系列，新增 src/platform/<chip>/ 做实例映射和时钟树。
  • 顶层 Kconfig 增加平台 choice，CMake 增加对应分支。

UART DMA / EXTI（默认关闭）

DMA/EXTI 框架已实现，默认走 IT；f407ve-dma 启用 UART1 DMA 与 pin EXTI，时序需上板验证。 实现时保持现有 API 不变，在 drv_serial 内增加 RX DMA + IDLE、TX DMA 完成回调， 并保留 IT 回退路径。

启用动态堆（不推荐）

RT_USING_HEAP=y 时 board.c 会在 _ebss 与保留 MSP 栈之间初始化堆，main 线程会改用 rt_thread_create。这会引入分配失败和碎片风险，默认保持关闭。

故障排查

先确认“构建 → 符号 → 串口 → LCD → 协议”这条链路，再定位具体层。

Build / 01

找不到工具链

从工程根目录使用 preset；确认 arm-none-eabi-gcc 在 PATH。自定义工具链时传绝对路径的 toolchain file。

Build / 02

GCC 14 汇编报 IT block

说明 context_gcc.S 被替换成未打补丁的 Nano 版本。按 UPSTREAM.md 补 4 处 IT EQ/NE。

Config / 03

menuconfig 打不开

Windows 需要 python -m pip install -r tools/requirements.txt；确认终端支持 curses。

Config / 04

切换 HSE 不生效

旧的 .config 不会被覆盖。使用新的 build 目录，或删除已有 .config 后重新配置。

Serial / 05

串口没有 banner

检查 PA9/PA10 是否交叉、共地、115200 8N1；确认 USART1 时钟/引脚配置。启动 banner 使用轮询发送。

Serial / 06

HIL 一直等第一帧

确认固件已过 LCD 初始化并进入 RPC 任务循环；等待 0x90 最多几秒。可用逻辑分析仪先看 PA9 是否有数据。

LCD / 07

LCD 黑屏 / 颜色异常

先确认背光极性与供电；再检查 SPI1 PA5/PA7、CS/DC/RES；边缘偏移调 X/Y offset，红蓝反了调 MADCTL。

Runtime / 08

HardFault / 卡死

检查是否在 ISR 调用了阻塞 API、是否忘记 arm RX、是否在启动前调用 LCD；确认 entry 与向量表正常。

版本与边界

  • 固件：Embedded Framework v2 · REV 1.0 · 2026-10-21。
  • 内核：RT-Thread Nano 3.1.5（官方 pack）。
  • CMake/Keil 共用 profiles 与 project/sources.json。
  • 默认 UART IT；DMA 预留。
  • Keil MDK + ARMCC 5（AC5）；AC6 未适配。
  • 无 FinSH / msh、ulog、RT-Thread device framework、动态堆。
  • 真实硬件 HIL 尚未在本手册编写环境执行。
维护建议 修改内核或 HAL 后，先跑 Host 测试，再构建两条 ARM 链路；上板前用 nm 检查强符号归属，最后跑 HIL。
