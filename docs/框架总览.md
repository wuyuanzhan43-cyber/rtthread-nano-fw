## 1. 项目定位

### 1.1 目标

这个工程不是“再封装一遍 HAL”，而是一套面向中小型 MCU 项目的**可移植设备框架**：

- 设备按路径访问：`fw_dev_find("serial1")`、`fw_dev_find("i2c1")`；
- 设备类（pin/serial/spi/i2c/adc/pwm/display）与芯片驱动分离；
- 板级只保留一个组合根和一份接线事实源；
- 全静态分配，不使用 `malloc`，RAM 可预测；
- Host 上可编译、可测试设备类与协议逻辑；
- Kconfig 只管理构建策略，板级接线用 C 表手写；
- CMake 与 Keil AC5 共用同一份源文件清单和同一套板级事实。

### 1.2 非目标

- 不实现完整 RT-Thread device framework、FinSH/msh、ulog；
- 不提供动态设备树、热插拔、设备自动发现；
- 不追求覆盖 STM32F4 全部外设，只实现当前项目验证过的子集；
- 不替代数据手册和 HIL：AF、DMA 请求映射、电气时序仍需上板验证；
- 不提供 AC6/ARMCLANG 工程（当前只适配 AC5）。

### 1.3 技术栈

| 项目 | 选择 |
|---|---|
| MCU | STM32F407VE，Cortex-M4F |
| 内核 | RT-Thread Nano 3.1.5（官方 pack，含 GCC 14 IT-block 补丁） |
| HAL | STM32F4xx HAL Driver V1.8.3 子集 |
| 构建 | CMake 3.21+ / ARM GNU Toolchain 14.2 |
| IDE | Keil MDK + ARMCC 5.06 update 5（AC5） |
| 配置 | Kconfig + `tools/genconfig.py` |
| 测试 | Host CTest + Python unittest + 串口 HIL 脚本 |

### 2.2 依赖红线

1. `framework` 不包含 HAL/RT-Thread 头（`port/rtthread` 除外）。
2. `platform/stm32f407` 不包含 `board_config.h`，只接收 `drv_*_hw_t`。
3. `board.c` 认识具体芯片和具体板子；驱动只认识芯片。
4. 业务命令、启动画面、图片只能放在 `src/app`。
5. 所有设备、ring、任务栈、DMA 缓冲静态分配。
6. 源文件清单只有 `project/sources.json`，CMake 与 Keil 共用。

### 2.3 目录

## 3. 启动流程

### 3.1 从复位到 main

```text
Reset_Handler
  → SystemInit
  → RT-Thread entry
  → rtthread_startup
  → rt_hw_board_init()
       stm32f407_boot_init(&s_clock)
         HAL_Init / NVIC 分组 4 / 时钟树 / SysTick / heap / 复位原因
       board_devices_init()
         system    fault 钩子 + DMA owner 表
         pins      接线结构校验
         pin       "pin" 设备
         led       LED 输出
         serial    serialN + 控制台绑定
         spi/i2c/adc/pwm
         storage   NVM 后端 + fw_param 扫描
         display   "lcd"
       rt_components_board_init()（若启用）
  → main_thread_entry
  → main()
```

### 3.2 main 的顺序

```text
main
  fw_rtthread_log_bind()
  fw_dev_open(console)
  fw_dev_open(pin)
  board_serial_start_all()      // 打开 UART NVIC
  app_boot_display(board_lcd())
  app_tasks_init()              // adopt main + create rpc + worker
  app_rpc_init()
  app_tasks_start()
  board_watchdog_start()        // 可选
  监督循环：
    fw_task_refresh()
    若 summary.lost == 0 → board_watchdog_feed()
    fw_task_next_wait_ms() → rt_thread_mdelay()
```

关键点：

- 设备注册在调度器启动前完成，注册表之后只读；
- UART 中断在 `board_serial_start_all()` 之后才打开，避免启动早期 ISR；
- LCD 真正初始化在 main 线程，不在 `rt_hw_board_init` 中；
- 看门狗在所有任务启动后才开启，只有健康检查通过才喂狗。

## 4. 设备模型

### 4.1 三个核心结构

```text
fw_dev_t          设备基类：name / type / ref_count / ops / drv / error_count
fw_drv_t          驱动描述：type / ops（具体类 ops）/ data（驱动实例）
fw_dev_ops_t      类级操作：open / close / read / write / ioctl / isr
```

- `fw_dev_t` 必须是具体设备结构体的**第一个成员**；
- `FW_CONTAINER_OF` 从基类反推外层对象；
- 注册表是固定容量数组，线性查找，不使用动态内存；
- 设备名支持 `"serial1"` 与 `"/dev/serial1"` 两种写法；
- 注册后 `dev->ops` 指向类级分发函数，`dev->drv->ops` 指向驱动 ops。

### 4.2 注册流程

```c
fw_dev_register(&dev, "name", FW_DEV_TYPE_XXX, &drv);
dev.ops = &class_dev_ops;
```

以 I2C 为例：

```text
drv_i2c_register_all(hw, count)
  → i2c_init_instance()
      配置 GPIO、打开时钟、HAL_I2C_Init
      填充 drv.type / drv.ops / drv.data
  → fw_i2c_register()
      → fw_dev_register()
      → i2c->dev.ops = &i2c_dev_ops
```

### 4.3 打开与引用计数

- 第一次 `fw_dev_open()`：`ref_count 0→1`，调用 `ops->open`；
- 重复 open：只增加计数；
- 最后一次 close：调用 `ops->close`；
- 未 open 就 close 返回 `FW_EINVAL`；
- `fw_dev_read/write/ioctl/isr` 统一做参数检查后转发给 ops。

### 4.4 错误计数

类层在驱动返回负值时调用 `fw_dev_note_error(dev)`；计数只增不减，由
`fw_dev_error_count()` 读取。计数非原子，要求同一设备单 owner 使用。

## 5. 设备类与 API

| 设备名 | 类 | 主要 API | 语义 |
|---|---|---|---|
| `pin` | pin | `fw_pin_configure/read/write/attach` | 一个设备覆盖所有 GPIO；`offset=(port<<4)|pin` |
| `serial1..N` | serial | `fw_serial_read/write/wait_rx/flush` | IT 或 DMA；静态 ring |
| `spi1..N` | spi | `fw_spi_transfer` / `_async` / `_wait` / `_abort` | 同步/异步；DMA 可选 |
| `i2c1..3` | i2c | `fw_i2c_transfer/mem_read/mem_write/probe` | 7 位地址；阻塞主模式 |
| `adc1` | adc | `fw_adc_read/read_mv` | 单通道单次轮询 |
| `pwm4` | pwm | `fw_pwm_set_duty/start/stop/get_config` | TIM4 四路；千分比 |
| `lcd` | display | `fw_display_setup/fill/fill_rect/...` | ST7735S，使用 `spiN + pin` |

### 5.1 serial

- 每个启用 UART 一个设备，名字 `serialN`；
- RX/TX ring 大小由 `FW_SERIAL_RX_BUFSZ/TX_BUFSZ` 决定；
- 默认走 RXNE/TXE 中断；`FW_USING_UARTn_DMA_RX/TX` 可切 DMA；
- DMA 路径仍由类层持有 ring，驱动通过 `rx_push/tx_peek/tx_consume` 访问；
- `fw_serial_wait_rx()` 支持超时；RPC 任务用它等待帧。

### 5.2 SPI

| API | 语义 |
|---|---|
| `fw_spi_transfer` | 阻塞；有异步在途时返回 `FW_EBUSY` |
| `fw_spi_transfer_async` | 启动后立即返回 length，busy=1 |
| `fw_spi_transfer_wait` | 等待完成；0 表示只轮询 |
| `fw_spi_transfer_abort` | 取消在途传输；未忙时幂等 |

- async/wait/abort 必须“全有或全无”，注册期校验；
- 同步传输在 DMA 打开且长度 ≥16 时自动走 async+wait；
- TX/RX 缓冲和 CS 在 wait/abort 返回前必须保持有效；
- 类层只维护 busy，信号量和 HAL 回调在 platform 驱动。

### 5.3 I2C / ADC / PWM

- **I2C**：7 位地址；`mem_read` 使用 repeated start；写后读是两个 STOP；
- **ADC**：一个设备覆盖所有已接线通道；`fw_adc_read_mv` 做 mV 换算；
- **PWM**：通道 0..3 对应 TIM4 CH1..4；占空比千分比；start/stop 是全局；
- 三者首版全部阻塞/轮询，不使用中断/DMA。

### 5.4 display

- `lcd` 是显示设备，不直接操作 SPI；
- ST7735S 驱动使用 `spiN` 和 `pin` 设备，负责 CS/DC/RES/BL；
- 实际面板初始化由 `fw_display_setup()` 在 main 线程执行；
- 应用通过 `app_boot_display(board_lcd())` 获取设备。

## 6. 板级模型

### 6.1 单文件组合根

板级目录只有 6 个文件：

```text
src/platform/board/stm32f407ve/
  board.c           单文件组合根
  board.h           应用可见 API
  board_config.h    手写纯 C 接线事实源
  Kconfig.board     构建策略
  link.lds          GCC 内存布局
  BOARD.md          人读接线表
```

这是 mr-library 风格的核心：**一块板一个组合根 + 一组静态 C 表**。
不再有 `board_devices.c`、`board_pins.c`、`board_clock.c` 等拆分文件。

### 6.2 board_config.h

只依赖 `<stdbool.h>`、`<stdint.h>` 和生成的 `board_policy.h`，不包含
HAL/RTOS/驱动头，因此 Host 测试可以直接包含。

包含：

- 身份、内存/NVM、Keil 器件字段；
- 逻辑引脚表：LED、LCD CS/DC/RES/BL；
- UART/SPI/I2C/ADC/PWM 通道表；
- DMA 路由：`{controller, stream, channel}`；
- LCD 面板参数：分辨率、偏移、MADCTL、反色、背光极性；
- 策略默认值与编译期检查。

### 6.3 board.c

按“校验 → pin → 外设 → 存储 → LCD”顺序完成：

```text
board_pins_validate()
build_serial_hw() / build_spi_hw() / build_i2c_hw() /
build_adc_hw() / build_pwm_hw()
drv_*_register_all()
stm32f407_console_bind()
stm32f407_nvm_init() + fw_param_init()
st7735s_init()
```

所有失败都返回 `fw_status_t`；`board_devices_init()` 打印失败步骤并返回，
`rt_hw_board_init()` 随后 panic。

### 6.4 默认接线摘要

| 功能 | 信号 | 引脚 | 说明 |
|---|---|---|---|
| LED | — | PE2 | 高有效 |
| console | USART1 TX/RX | PA9/PA10 | AF7，115200 |
| SPI1 | SCK/MISO/MOSI | PA5/PA6/PA7 | AF5；MISO 默认关闭 |
| I2C1 | SCL/SDA | PB6/PB7 | AF4，100 kHz |
| ADC1 | IN8/IN9 | PB0/PB1 | 12 位，Vref 3.3V |
| PWM4 | CH1..4 | PD12..PD15 | AF2，1 kHz |
| LCD | CS/DC/RES/BL | PA4/PA6/PA3/PA2 | ST7735S 128×160 |

完整接线、DMA 路由和 ILI 面板参数见
[`src/platform/board/stm32f407ve/BOARD.md`](../src/platform/board/stm32f407ve/BOARD.md)。

### 6.5 内存布局

| 区域 | 起始 | 大小 | 用途 |
|---|---|---|---|
| FLASH（代码区） | `0x08000000` | 256KB | 向量、代码、只读数据、.data 初值 |
| NVM | `0x08040000` | 256KB | 参数 A/B 槽，不参与链接 |
| RAM | `0x20000000` | 128KB | .data/.bss/栈/RT-Thread 对象/DMA 缓冲 |
| CCM | `0x10000000` | 64KB | 当前不使用（DMA 不能访问） |

- GCC：`link.lds` 内联这些区域；
- Keil：`gen_keil.py` 从 `board_config.h` 派生 IROM/IRAM/Stack；
- NVM 后端：`stm32f407_nvm.c` 使用绝对地址访问；
- `tools/tests/test_static_board.py` 交叉校验三者一致。

## 8. 内存与 NVM

### 8.1 参数存储

```text
0x08040000 ┌──────────────────────────────┐
           │ slot A 128KB                 │
0x08060000 ├──────────────────────────────┤
           │ slot B 128KB                 │
0x08080000 └──────────────────────────────┘
```

- 槽头 20 字节：magic / version / sequence / size / crc32；
- `fw_param_save()`：擦除非活动槽 → 写槽头 → 写数据 → 回读校验 → 切换；
- `fw_param_init()`：选择序号最高且 CRC 有效的槽；
- 掉电写坏一个槽时，下一次 init 回退到另一个槽；
- 每次 save 擦除整个 128KB 扇区，适合低频参数，不适合高频写入。

### 8.2 代码区与 NVM 的一致性

以下三处必须一致：

1. `board_config.h` 的 `BOARD_CODE_FLASH_SIZE_KB` / `BOARD_NVM_ORIGIN`；
2. `link.lds` 的 FLASH/NVM 区域；
3. Keil uvprojx 的 IROM 和 sct 的 LR_IROM1。

Host CTest 会通过 `test_static_board.py` 交叉检查；只改一处会失败。

## 9. 可靠性与诊断

### 9.1 Fault

- HardFault：由 RT-Thread 异常入口接管，安装 `rt_hw_exception_install` 钩子；
- MemManage/BusFault/UsageFault：本模块提供强符号入口；
- 输出：R0-R3/R12/LR/PC/xPSR 栈帧、CFSR、HFSR、MMFAR、BFAR；
- `BOARD_FAULT_RESET=1` 时输出后复位；默认停机，便于调试器检查；
- 故障现场使用控制台直写，不经过 ring/中断。

### 9.2 Panic

`stm32f407_panic(file, line)` 输出文件/行号并直写串口；可与 fault 共用
复位策略。

### 9.3 IWDG

- `BOARD_IWDG_ENABLE=1` 时 main 在任务全部启动后开启；
- 只有 `fw_task_summary().lost == 0` 时才喂狗；
- LSI 32kHz 估算，实际超时随芯片偏差浮动；
- 启动后不可停止，长时间断点调试应关闭。

### 9.4 日志

- `FW_LOGE/W/I/D` 宏；`FW_LOG_LEVEL` 编译期裁剪；
- 运行期 `fw_log_set_level()` 只能降低；
- sink 由 RT-Thread 端口绑定到 `rt_hw_console_output`；
- 128 字节行缓冲，不可重入，只在任务上下文使用；
- fault/panic 不走 fw_log。

### 9.5 设备错误计数

每个 `fw_dev_t` 有 `error_count`；类层在驱动返回负值时累加；可用
`fw_dev_error_count()` 或调试器读取。

## 10. 任务健康与 RPC

### 10.1 任务管理

- `fw_task` 与 RTOS 无关；线程操作通过 `fw_task_port_ops_t`；
- `main` 作为监督者，adopt 自身，创建 `rpc` 与可控 `worker`；
- 健康指标：栈剩余、CPU 占用、线程状态、心跳 warn/lost；
- 挂起是协作式：control 只置 pending，目标任务在 `heartbeat_self` 中自行挂起；
- 健康异常只标记并上报，不自动重启。

### 10.2 线协议

```text
A5 5A LEN SEQ CMD PAYLOAD CRC_LO CRC_HI

0x01 PING
0x02 LED_SET
0x03 STATUS
0x04 STATS
0x05 TASK_SUMMARY
0x06 TASK_DETAIL
0x07 TASK_CONTROL
0x90 EVENT（设备主动上报）
```

- `0x05`：13 字节摘要（total/ok/warn/lost、worst/current、busy/idle/other）；
- `0x06`：请求 1 字节索引；回复 31 字节详情；
- `0x07`：请求 `index/action/value`；suspend 为协作式 pending；
- 帧层使用 CRC-16/CCITT-FALSE。

### 10.3 HIL

```text

```

## 12. 扩展指南

### 12.1 启用已有实例

只改 Kconfig 的 `FW_USING_UARTn/SPIn/I2Cn/ADC1/PWM4`；`board.c` 会自动
从 C 表过滤并注册，不需要写注册代码。

### 12.2 在已有总线上挂新器件

- 简单场景：直接 `fw_dev_find("i2c1")` + `fw_i2c_mem_read`；
- 需要命名设备：实现 `fw_dev_ops_t`，调用 `fw_dev_register`；
- 新增 `FW_DEV_TYPE_*` 令牌；
- 在 `board.c` 的总线初始化之后注册。

### 12.3 新增完整设备类

以 DAC 为例：

```text
fw/dev.h                 追加 FW_DEV_TYPE_DAC
fw/dac.h                 ops / config / fw_dac_t / register
core/fw_dac.c            类级分发 + fw_dev_register
platform/stm32f407/drv_dac.h/.c
                         芯片驱动 + drv_dac_register_all
board_config.h           实例/引脚 C 表
board.c                  build_dac_hw + board_dac_init
project/sources.json     登记源文件
```

详细步骤见 [`docs/新设备注册指南.html`](新设备注册指南.html)。

### 12.4 换板

1. 复制 `src/platform/board/stm32f407ve/` 到新板目录；
2. 改 `board_config.h` 的引脚/通道/内存/NVM/LCD；
3. 改 `Kconfig.board` 的策略项；
4. 改 `link.lds` 的内存区域；
5. 更新 `project/sources.json` 的 `board_sources` 和顶层 Kconfig/CMake 平台分支；
6. `sync --all`、`gen-keil`、构建、Host 测试。

同一芯片系列可复用 `src/platform/stm32f407`；换芯片系列需要新的 platform
驱动、映射和时钟树。

## 13. 约束与已知边界

1. 内核为 RT-Thread Nano 3.1.5；无 FinSH/msh、ulog、RT-Thread device framework。
2. 全静态分配，`RT_USING_HEAP=n`；设备表、ring、任务栈、DMA 缓冲均静态。
3. SPI1 的 MISO（PA6）与 LCD DC 共用，默认 `USE_MISO=0`，只能 TX；
   全双工请使用 SPI2/SPI3 或改接线。
4. I2C/ADC/PWM 首版全部阻塞/轮询；I2C 400 kHz 需要外部上拉。
5. ADC 未调用校准 API；PWM 在 ARR=65535 时 100% 占空比会轻微钳位。
6. NVM 每次 save 擦除整个 128KB 槽，适合低频参数。
7. Fault dump 在控制台绑定前不可用；日志缓冲不可重入。
8. 构建链：CMake + ARM GCC；Keil MDK + AC5；AC6 未适配。
9. Keil 工程生成一致不等于完整编译通过，最终以 UV4 构建为准。
10. 未上板前不声称硬件验证完成；AF/DMA/时序必须 HIL。
